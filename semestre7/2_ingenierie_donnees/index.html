    Module 2 : Ingénierie et Analyse de Données

    Objectif du cours : Comprendre comment les entreprises modernes construisent des systèmes robustes pour collecter, stocker et transformer les données. Vous découvrirez les concepts de la "Modern Data Stack", les différences entre Data Lake et Data Warehouse, et le rôle crucial de l'ingénieur de données.

    1. L'Écosystème des Données : Plus qu'un Pipeline

    Si l'IA est le moteur d'une voiture de course, l'ingénierie des données est toute l'écurie derrière : les mécaniciens, le carburant, les systèmes de télémétrie... Sans une fondation de données solide, le meilleur modèle d'IA reste au garage.

    Le rôle de l'Ingénieur de Données (Data Engineer) est de construire et maintenir cette fondation. Il s'assure que les données sont disponibles, fiables et accessibles pour les Analystes de Données (Data Analysts) et les Scientifiques des Données (Data Scientists).

    2. L'Architecture Moderne : La "Modern Data Stack"

    Le processus ETL classique a évolué. Aujourd'hui, on parle de la "Modern Data Stack", une approche modulaire basée sur des outils cloud spécialisés. Le paradigme dominant est l'ELT (Extract, Load, Transform).

    1. Extract & Load : On utilise des outils automatisés (comme Fivetran ou Airbyte) pour extraire les données de leurs sources (applications, bases de données, API) et les charger brutes dans une destination centrale.

    2. Store (Stocker) : La destination est un Data Warehouse Cloud (comme Snowflake, Google BigQuery, ou Amazon Redshift). C'est le cœur du système.

    3. Transform : Une fois les données dans le Warehouse, on les transforme en utilisant principalement du SQL. C'est là que la logique métier est appliquée pour nettoyer, joindre et agréger les données, les préparant pour l'analyse. L'outil de référence pour orchestrer ces transformations est dbt (Data Build Tool).

    Pourquoi ELT est devenu la norme ?

    Le coût du stockage dans le cloud a chuté, il est donc plus simple de tout stocker d'abord et de transformer ensuite. Cela offre plus de flexibilité : les données brutes sont toujours disponibles si les besoins d'analyse changent.

    3. Data Warehouse vs. Data Lake : Deux Concepts Clés

    Caractéristique Data Warehouse (Entrepôt) Data Lake (Lac)
    Nature des données Structurées, traitées, nettoyées Brutes, non structurées (images, logs, PDF...)
    Schéma Schéma défini à l'écriture (Schema-on-Write) Schéma défini à la lecture (Schema-on-Read)
    Utilisateurs Analystes d'affaires, pour le reporting et la BI Data Scientists, pour l'exploration et le ML
    Cas d'usage Tableaux de bord, indicateurs de performance Entraînement de modèles de ML, analyse exploratoire

    Aujourd'hui, la frontière s'estompe avec le concept de "Lakehouse" (proposé par Databricks), qui vise à combiner la flexibilité d'un Data Lake avec la fiabilité et les performances d'un Data Warehouse.

    4. Le Rôle de l'Analyste : De la Donnée à l'Insight

    Une fois les données transformées et modélisées par l'ingénieur, l'Analyste de Données prend le relais. Son rôle est de :

    1. Explorer les données pour comprendre les tendances et les motifs (Analyse Exploratoire de Données - EDA).

    2. Construire des tableaux de bord (dashboards) et des visualisations pour suivre les indicateurs de performance (KPIs). Outils : Tableau, Power BI, Looker.

    3. Répondre à des questions métier en interrogeant les données, principalement avec SQL.

    C'est le travail de l'analyste qui transforme les données propres en décisions éclairées.
